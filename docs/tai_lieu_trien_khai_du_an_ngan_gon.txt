## 2.2. Quy tắc xử lý

```text
Controller
    ↓
Service
    ↓
DbContext
    ↓
Database
```

Controller:

- Nhận request.
- Kiểm tra dữ liệu cơ bản.
- Gọi Service.
- Trả response.

Service:

- Xử lý nghiệp vụ.
- Kiểm tra trạng thái.
- Kiểm tra quyền.
- Xử lý transaction khi cần.
- Gọi DbContext.

DbContext:

- Đọc dữ liệu.
- Ghi dữ liệu.
- Quản lý Entity Framework.

Không viết nghiệp vụ phức tạp trực tiếp trong Controller.

# 3. QUY TẮC ĐẶT TÊN

## 3.1. Tên file

Tên file phải ngắn và đúng đối tượng.

Dùng:

```text
TaiKhoan.cs
SuKien.cs
DonVe.cs
ThanhToan.cs
Ve.cs
```

Không dùng nếu không cần:

```text
TaiKhoanEntity.cs
TaiKhoanModel.cs
TaiKhoanDataModel.cs
SuKienEntityModel.cs
```

## 3.2. Tên class

Tên class trùng với tên đối tượng.

Ví dụ:

```csharp
public class TaiKhoan
{
}
```

```csharp
public class SuKien
{
}
```

```csharp
public class DonVe
{
}
```

## 3.3. Tên thuộc tính

Tên thuộc tính phải:

- Ngắn.
- Rõ nghĩa.
- Không lặp tên bảng khi không cần.
- Dùng PascalCase.

Ví dụ:

Không nên:

```csharp
public int IDTaiKhoan { get; set; }
public string TenTaiKhoanNguoiDung { get; set; }
public string DiaChiEmailTaiKhoan { get; set; }
```

Nên dùng:

```csharp
public int Id { get; set; }
public string HoTen { get; set; }
public string Email { get; set; }
```

Ví dụ `TaiKhoan.cs`:

```csharp
public class TaiKhoan
{
    public int Id { get; set; }

    public string HoTen { get; set; } = "";

    public string Email { get; set; } = "";

    public string MatKhau { get; set; } = "";

    public int VaiTroId { get; set; }

    public bool HoatDong { get; set; }

    public DateTime NgayTao { get; set; }
}
```

## 3.4. Khóa ngoại

Khóa ngoại viết theo dạng:

```text
<TenDoiTuong>Id
```

Ví dụ:

```csharp
public int TaiKhoanId { get; set; }

public int SuKienId { get; set; }

public int LoaiVeId { get; set; }

public int DonVeId { get; set; }
```

Không dùng:

```text
IDTaiKhoanNguoiDung
IDSuKienCuaBanToChuc
MaDinhDanhLoaiVe
```

## 3.5. Navigation Property

Dùng tên đối tượng trực tiếp.

Ví dụ:

```csharp
public TaiKhoan TaiKhoan { get; set; } = null!;
```

Quan hệ nhiều:

```csharp
public ICollection<SuKien> SuKiens { get; set; } = [];
```

## 3.6. Tên biến trong hàm

Dùng camelCase.

Ví dụ:

```csharp
var taiKhoan = await db.TaiKhoans.FindAsync(id);
```

```csharp
var suKien = await db.SuKiens.FindAsync(id);
```

```csharp
var don = await db.DonVes.FindAsync(id);
```

Không dùng:

```csharp
var taiKhoanNguoiDungHienTai;
var thongTinChiTietDonVeCuaNguoiDung;
var duLieuSuKienCanDuocCapNhat;
```

Nên dùng:

```csharp

var don;
var suKien;
var ve;
var thanhToan;
```

Nếu cần rõ hơn:

```csharp
var donHienTai;
var veConLai;
var tongTien;
var soLuong;
```

## 3.7. Tên hàm

Tên hàm cần ngắn và thể hiện hành động.

Ví dụ:


Có thể dùng hậu tố `Service` vì cần phân biệt với Entity.

Ví dụ:

# 4. PHÂN QUYỀN

## 4.1. NguoiDung

Có quyền:

- Quản lý tài khoản cá nhân.
- Gửi yêu cầu xác thực ban tổ chức.
- Xem sự kiện.
- Mua vé.
- Xem đơn của mình.
- Xem vé của mình.

## 4.2. BanToChuc

Có toàn bộ quyền của `NguoiDung`.

Ngoài ra:

- Tạo sự kiện.
- Sửa sự kiện của mình.
- Quản lý sự kiện của mình.
- Đặt địa điểm.
- Tạo loại vé.
- Quản lý loại vé.
- Theo dõi đơn vé của sự kiện mình quản lý.
- Theo dõi vé của sự kiện mình quản lý.

## 4.3. QuanLySuKien

Có quyền:

- Xem yêu cầu xác thực.
- Duyệt yêu cầu xác thực.
- Từ chối yêu cầu xác thực.
- Xem sự kiện chờ duyệt.
- Duyệt sự kiện.
- Từ chối sự kiện.
- Theo dõi sự kiện.
- Check-in vé theo quyền được cấp.

## 4.4. QuanTriVien

Có quyền:

- Quản lý tài khoản.
- Quản lý vai trò.
- Khóa tài khoản.
- Mở khóa tài khoản.
- Quản lý loại sự kiện.
- Quản lý địa điểm.
- Theo dõi toàn hệ thống.
- Xem thống kê.
- Quản trị dữ liệu.

## 4.5. Quy tắc bắt buộc

Backend phải kiểm tra:

```text
Tài khoản đang hoạt động
        ↓
Đúng vai trò
        ↓
Đúng quyền
        ↓
Đúng chủ sở hữu dữ liệu
        ↓
Mới cho phép thao tác
```

Không được chỉ kiểm tra quyền ở frontend.

# 6. QUY TẮC NGHIỆP VỤ

1. Một tài khoản chỉ được có tối đa một yêu cầu xác thực hiện hành.

2. Chỉ `BanToChuc` đã xác thực và tài khoản đang hoạt động mới được tạo sự kiện.

3. Người tạo sự kiện không được tự duyệt sự kiện.

4. Thời gian kết thúc sự kiện phải lớn hơn thời gian bắt đầu.

5. Không được đặt cùng một địa điểm bị trùng thời gian.

6. Chỉ sự kiện đã duyệt mới được bán vé.

7. Thời gian đóng bán phải sau thời gian mở bán.

8. Số vé đã bán và đang giữ không được vượt số lượng tối đa.

```text
DaBan + DangGiu <= ToiDa
```

9. Backend tự tính toàn bộ tiền của đơn.

10. Không tin giá hoặc tổng tiền do frontend gửi.

11. Giữ vé phải dùng transaction.

12. Đơn hết hạn hoặc bị hủy phải trả lại số lượng vé đang giữ.

13. Webhook thanh toán phải được xác minh.

14. Webhook phải chống xử lý lặp.

15. Chỉ tạo vé sau khi thanh toán thành công.

16. Không được hoàn tiền nhiều hơn số tiền đã thanh toán.

17. Hoàn tiền phải tham chiếu giao dịch thanh toán gốc.

18. Không xóa tùy tiện:

```text
ThanhToan
Ve
LichSu
Audit
```

19. `RowVersion` không thay thế transaction hoặc locking.

# 11. VALIDATION

# 11.1. TaiKhoan

Kiểm tra:

- Email đúng định dạng.
- Email không được trùng.
- Mật khẩu phải hash.
- Tài khoản bị khóa không được thực hiện thao tác bảo vệ.

Ví dụ thuộc tính:

```csharp
public class TaiKhoan
{
    public int Id { get; set; }

    public string HoTen { get; set; } = "";

    public string Email { get; set; } = "";

    public string MatKhau { get; set; } = "";

    public int VaiTroId { get; set; }

    public bool HoatDong { get; set; }

    public DateTime NgayTao { get; set; }
}
```

---

# 11.2. SuKien

Kiểm tra:

```text
KetThuc > BatDau
```

- Số lượng người dự kiến phải lớn hơn 0.
- Loại sự kiện phải đang hoạt động.

Tên thuộc tính gợi ý:

```csharp
public DateTime BatDau { get; set; }

public DateTime KetThuc { get; set; }

public int SoNguoi { get; set; }
```

Không cần dùng:

```csharp
ThoiGianBatDauSuKien
ThoiGianKetThucSuKien
SoLuongNguoiDuKienThamGiaSuKien
```

---

# 11.3. DiaDiem

# 12.1. Giữ vé

Luồng:

```text
Begin Transaction
        ↓
Kiểm tra vé còn
        ↓
Tăng DangGiu
        ↓
Tạo DonVe
        ↓
Tạo ChiTietDonVe
        ↓
SaveChanges
        ↓
Commit
```

Nếu lỗi:

```text
Rollback
```

Ví dụ biến:

```csharp
var loaiVe;
var soLuong;
var don;
var chiTiet;
```

Không cần dùng:

```csharp
var thongTinLoaiVeHienTaiCanDuocDat;
```

---

# 12.2. Đơn hết hạn hoặc hủy

```text
Begin Transaction
        ↓
Giảm DangGiu
        ↓
Cập nhật trạng thái đơn
        ↓
SaveChanges
        ↓
Commit
```

---

# 12.3. Thanh toán thành công

```text
Nhận webhook
        ↓
Verify
        ↓
Kiểm tra đã xử lý chưa
        ↓
Begin Transaction
        ↓
Giảm DangGiu
        ↓
Tăng DaBan
        ↓
Cập nhật DonVe
        ↓
Tạo Ve
        ↓
SaveChanges
        ↓
Commit
```

Webhook phải idempotent.

Có nghĩa là:

```text
Một giao dịch gửi webhook 5 lần
```

thì hệ thống chỉ xử lý thành công:

```text
1 lần
```

# 12.4. Đặt địa điểm

```text
Begin Transaction
        ↓
Kiểm tra lịch
        ↓
Kiểm tra giao nhau
        ↓
Tạo DatDiaDiem
        ↓
SaveChanges
        ↓
Commit
```

Nếu có request khác đặt cùng thời gian:

```text
Chỉ một request được thành công.
```

# 20. NGUYÊN TẮC CUỐI

Code phải ưu tiên:

```text
Ngắn
Rõ
Dễ đọc
Dễ tìm
Dễ sửa
```

Không cố làm kiến trúc quá phức tạp.

Không tạo class chỉ để cho "đúng mô hình" nếu class đó chưa có tác dụng thực tế.

Không chia một chức năng nhỏ thành quá nhiều file.

Không dùng tên dài chỉ để mô tả toàn bộ ý nghĩa trong tên biến.

Tên chỉ cần đủ để hiểu trong ngữ cảnh.

Ví dụ tốt:

```csharp
var don = await db.DonVes.FindAsync(id);

if (don == null)
    return null;

if (don.TrangThai != TrangThaiDon.ChoThanhToan)
    throw new Exception("Đơn không hợp lệ.");
```

Thay vì:

```csharp
var thongTinDonVeCuaNguoiDungCanDuocXuLy =
    await db.DonVes.FindAsync(id);
```

# 22. LƯU Ý

- Request/response DTO thiết kế khi làm từng phase.
- UI chi tiết làm sau khi API tương ứng ổn định.
- Quyền giữa `BanToChuc`, `QuanLySuKien` và `QuanTriVien` phải kiểm tra ở backend.
- Không tin dữ liệu nhạy cảm từ frontend.
- Không tin giá tiền từ frontend.
- Không tin trạng thái thanh toán từ frontend.
- Các thao tác vé, đơn, thanh toán và đặt địa điểm cần chú ý concurrency.
- Không bỏ transaction ở các nghiệp vụ liên quan số lượng vé.
- Không cho chuyển trạng thái Entity tự do.
- Không xóa lịch sử tài chính và vé tùy tiện.
- Ưu tiên tên class, biến và thuộc tính ngắn gọn, rõ nghĩa.
- Chỉ thêm hậu tố như `Service`, `Controller`, `Dto` khi cần phân biệt loại class.
